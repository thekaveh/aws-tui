# S3 and Local File Manager

The S3 service is a keyboard-driven, dual-pane file manager for AWS S3,
S3-compatible object stores, and the local filesystem. Each pane owns its own
source and current path, so local-to-S3, S3-to-local, and S3-to-S3 workflows
use the same navigation and transfer surface.

## 1. Sources and navigation

Each pane can use `local`, an explicit `[connections.*]` entry, or an
auto-discovered AWS profile. `Shift+S` cycles only the focused pane through
resolver order. The opposite pane and its selection remain unchanged.

`Tab` and `Shift+Tab` move between the left pane, right pane, and service rail.
`Enter` descends into the selected directory, bucket, or prefix;
`Backspace` ascends one level. See [Keybindings](../keybindings.md) for the
complete active map.

After repairing an expired or missing credential outside aws-tui, press `a`
or choose **Retry active source credentials** from the command palette. The retry stages fresh listings before changing either live pane. It preserves each matching pane's current path when it still exists. It falls back to remote root only when a saved non-root path no longer exists.

If both panes use the
same source, both staged reads must succeed before either pane changes. A
failure, cancellation, or source change leaves paths, entries, selections,
and the opposite local pane untouched.

## 2. File operations

`c` copies the selected row or marked rows to the opposite pane through the
streaming `CrossFsCopy` engine. The destination is the opposite pane's current
path plus each selected entry's name.

Directory copies can merge into an existing S3 directory/prefix under ERROR,
SKIP or RENAME. For example, copying local `source/` into `s3://bucket/uploads/`
targets `uploads/source/`. That merge root must already exist; an existing
`uploads/` parent alone is insufficient. A marker or existing children can
establish a prefix.

These policies apply independently to children:

| Policy | Source file at an occupied destination name | Matching source and destination directories |
| --- | --- | --- |
| ERROR | Refuse a known conflict during preflight. | Recursively merge their children. |
| SKIP | Skip that file and continue with other children. | Recursively merge; do not skip the whole directory. |
| RENAME | Choose a free leaf name, such as `one (1).txt`. | Recursively merge; do not rename the matching directory. |

If a source directory is blocked by a destination file, ERROR reports a conflict
and SKIP skips that subtree. RENAME would need a new directory tree and is
therefore refused on S3.

Creating an absent destination directory requires transactional publication.
This includes an absent nested subtree, even an empty one, inside an otherwise
existing merge root. Preflight checks the selected tree and refuses unsupported
cases before transferring payload bytes, including earlier copyable siblings.
Metadata reads can still occur. Known ERROR conflicts also fail during this preflight.

OVERWRITE for a selected directory means whole-tree replacement, not a merge
that overwrites each child. S3 does not support this directory transaction.
`LocalFS` supports transactional directory publication; `S3FS` does not.
This limitation is separate from single-file overwrite behavior.

An existing-prefix merge is **not whole-tree atomic**. A later error,
cancellation or destination race can leave earlier children published.
Inspect partial results before retrying; do not assume the whole merge rolled back.
For unsupported new-tree uploads, copy individual files or use another tool,
such as the AWS CLI.

`d` deletes the selected
rows. Both operations
require confirmation, reject a parent-link row, and publish progress through
the Transfers overlay. Persistent marks, range extension, and modifier-click
selection let one operation address multiple entries.

File-operation, selection and path shortcuts require a focused pane with a
ready listing. They do not act on retained rows while the service rail or
another control has focus, or while the pane is loading. Copy also requires
the destination listing to be ready.

If a listing, selection, path or source changes before a confirmed operation
starts, the application shows an expired-confirmation warning and leaves the
files unchanged. Review the current entries and repeat the operation.

`p` copies the full path of the entry under the cursor; `P` copies the
pane's current directory path. Both are also command-palette entries
(**Copy cursor entry path**, **Copy pane path**), listed only while the
file manager is the active service. The pane's top border is a click target for the same copy. A truncated name or path is revealed in full rather than silently clipped.

The confirmation names the channel that actually took the text. Where a
clipboard helper is available (`pbcopy`, `clip`, `wl-copy`, `xclip`,
`xsel`) the toast confirms the copy.

Where there is none — an ssh session, a container, a stripped-down host — the only write is the terminal's own OSC 52 escape. No terminal acknowledges it. Some terminals discard it (macOS Terminal.app always, iTerm2 unless enabled). The toast says so rather than claiming a copy that may not have happened.

S3 multipart copies and uploads are cancelled and aborted explicitly. Active
transfers write diagnostic journal records under `<cache-dir>/transfers/`;
terminal success, failure, skip, and cancellation persist a safe summary before
removing their journal. `Ctrl+T` opens History and Recovery, including after a
restart or after live progress rows expire. History retains the 100 newest
summaries.

To cancel one active transfer with the keyboard, press `Ctrl+K` and choose
**Focus active transfers**. Use `Tab` or `Shift+Tab` to choose an enabled
control, then `Enter` or `Space` to activate it. Cancellation stays in the
Transfers area so repeated activation cannot cancel a neighbor. Press `Tab`
to choose another control, or `Escape` to return to the service. Moving past
either end of the controls also returns to the service. The configurable
action `app.focus_transfers` has no default key.

Scroll the transfer cards with the mouse wheel to reach later transfers.
Click a card's **Cancel** control to cancel only that transfer.
The title and History / Recovery controls remain outside the scrolling area.

Interrupted outcomes stay unknown; explicit copy retries recheck
original connections and endpoints and ask for a fresh conflict choice. Clear
history removes validated metadata only, preserving files and active transfers. See the [recovery recipe](../cookbook.md#4-inspect-transfer-history-and-recovery-after-a-restart)
for retry refusals and uncertain publication. Move, rename, and new-folder commands remain deferred.

Local streaming reads accept regular files only. Named pipes and other special
files are rejected before a transfer or preview can wait for a writer.

Source inspection also needs `s3:ListBucket` access under the object’s `key/` prefix.
It checks for conflicting directory entries before a transfer can proceed.

S3 can contain both an object `k` and a directory prefix `k/`. Operations that
inspect a source path refuse that ambiguity before copy, move, or rename can
choose the wrong entry. Remove one of the conflicting names through the AWS
console or CLI before retrying.

## 3. Architecture

`S3Service` composes a `DualPaneVM` from two `PaneVM` instances. Providers
implement the shared `FileSystemProvider` protocol: `S3FS` for AWS or
S3-compatible sources and `LocalFS` for the workstation. `CrossFsCopy` owns
staging, commit, rollback, conflict handling, progress, and cancellation.
Textual widgets render VM state and route commands; they do not call providers
directly.

The source resolver supplies exact connection identity, region, endpoint,
addressing style, and credential references. The S3 provider uses the
aioboto3/botocore public client contract recorded in the
[Consumed Contract Ledger](../contract-ledger.md).

## 4. Safety and limits

- S3-compatible connections share the S3 implementation but may require
  path-style addressing or vendor-specific endpoint configuration.
- A directory listing is limited to 10,000 entries. S3 traversal is also
  limited to 100 continuation pages; narrow the current path when either
  safety budget is exceeded.
- One copy or move batch is limited to 1,000 selected entries. The limit is
  checked before durable transfer journals are created.
- Quick Look keeps a raw prefix of at most 64 KiB. Structured previews can read bounded additional ranges, including Parquet footer and sample data. They share a 32-request, 8 MiB budget; see [Quick Look](../cookbook.md#9-preview-files-with-quick-look).
- Transfer journals are diagnostics, not automatic replay instructions.
- The application never infers a destructive operation from navigation or
  selection alone.

Connection examples and provider configuration guidance are in
[Connections](../connections.md). Transfer recovery and local S3Mock recipes are in
the [Cookbook](../cookbook.md).

Demo mode seeds deterministic S3-compatible sources while leaving the local

## 6. Loaded listing controls

Use `/` to filter the current loaded prefix by name and `Ctrl+P` to find and
select a loaded entry. These controls never request another provider listing or
read an object. Escape retains live filtering; Clear restores loaded rows and
retained marks. Finding a hidden entry clears the filter on selection.

Choose
**Sort loaded entries** in the command palette for six name, size, or modification
time orders. See [keybindings](../keybindings.md#6-loaded-listing-controls) for
counts, missing metadata, reset rules, and selection semantics.

## 7. Current-object properties

On a focused S3 object row, press `Ctrl+O` or choose **S3 object details**
from the Commands command palette. The action is `pane.object_details`.
This is a read-only, on-demand view of the current object. Connection and
navigation controls, bucket and prefix rows, local files, parent links and
empty selections receive a visible refusal without a metadata read.

The property table shows content type, content encoding, size, last modified,
storage class, ETag, version ID, encryption summary, user metadata, tags and
available checksums. Move through fields with the arrow keys; the wrapping
**Full value** viewer below the table preserves long values and literal markup.

`Tab` moves through the table, viewer, **Copy** and **Close** controls.
**Copy** or `Ctrl+C` copies the complete selected value, including empty strings;
metadata, tags, encryption and checksums use lossless JSON. The existing
clipboard outcome toast distinguishes a confirmed helper write from an
unacknowledged terminal write. `Escape` or **Close** restores the unchanged
pane cursor, selected row and focus slot.

Missing or denied fields say **Unavailable** and cannot be copied. A returned
empty string says **(empty)**, and an empty returned map is `{}`; these are
copyable values. Denied tagging or checksum access leaves other properties
visible and marks only that section unavailable. Error text is redacted before
display.

A selection change clears old values and discards late replies; a
source or page replacement invalidates and closes the inspector. Closing or
unmounting cancels and drains its reads.

The inspector uses `HeadObject` and `GetObjectTagging`, without downloading
object content or issuing a mutating S3 call. It requires `s3:GetObject` and
`s3:GetObjectTagging`; tagging a reported version may require
`s3:GetObjectVersionTagging`. Optional SSE-KMS checksum reads may require
`kms:Decrypt` and `kms:GenerateDataKey`. A denied optional checksum read retries
ordinary HEAD so other properties remain available. Normal directory listing
adds no per-row `head_object` or `get_object_tagging` calls.

ETag and checksums are separate fields. Checksum verification is **Not
performed**: these are values reported by S3, not proof of a content match.
An ETag is not always an MD5 digest. Version ID is a reported property. This view does not browse object versions, edit metadata or tags, change ACLs or storage class, or create presigned URLs. Compatibility depends on the endpoint's
HEAD/tagging support and the session's permissions.

A listing with an empty directory name fails before a transfer can publish incomplete content.
For example, `daily//child` contains an empty component under `daily/`. Use [historical exact-key entry](#8-historical-object-versions) for retained versions of such keys.
Use the AWS console or CLI for current-object operations.

## 8. Historical object versions

To retrieve retained content, focus an S3 pane inside a bucket or prefix.
Open the command palette with `Ctrl+K`, then choose **S3 object versions**.
A selected file supplies the initial key.
For a deleted current object, enter its exact key relative to the displayed source prefix, then choose **List**.
Key entry preserves spaces, repeated separators and dot components.

The table shows only that key's versions and delete markers.
Use the arrow keys to select a row.
The wrapping viewer retains its full key, version ID, timestamp, size, latest flag and marker status.
**Inspect old** reads the selected version's properties.
Delete markers identify history but have no downloadable content.

**Download** retrieves the selected historical content into the opposite local pane.
Enter one filename, then review and confirm the source version and destination.
Existing files are refused.
**Recover NEW** creates a different key in the same bucket.
Enter a key relative to the original source prefix, then review and confirm it.
Recovery never replaces the current key or deletes a retained version.

Recovery preserves user metadata and tags from exact-version reads.
Preserved headers are content type, encoding, language, disposition, cache control, expiry and website redirect location.
Source ACLs, encryption settings, object locks and storage class are not copied.
Destination policies apply.

Unavailable or malformed required metadata and tag reads prevent recovery.
An empty tag set is valid.
Headers and tags are separate observations, not one atomic snapshot.
Reported checksums are not copied or verified.
A literal `null` version can change without changing its ID; detected changes are refused.

Both actions use the normal transfer progress and cancellation controls described above.
Cancellation aborts unfinished recovery uploads; a published new key is preserved.
If publication is uncertain, inspect the named destination before retrying.
Historical transfers cannot use generic History retries, which would lose their version identity.

Version discovery requires `s3:ListBucketVersions`; bucket-state reporting also uses `s3:GetBucketVersioning`.
Historical reads require `s3:GetObjectVersion`.
Recovery requires `s3:GetObjectVersionTagging` to read the selected version's tags.
Destination permissions include `s3:PutObject`, `s3:PutObjectTagging` when preserving tags, and `s3:AbortMultipartUpload`.
See the AWS [version-specific permission](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-with-s3-policy-actions.html) and [upload-permission](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html) contracts.
Endpoint support and encryption permissions can impose additional requirements.

Unversioned, suspended, unavailable and denied states have distinct messages.
S3 directory buckets do not support this workflow.
Listing stops after 100 pages or 10,000 scanned entries, including prefix neighbors.
Exceeding either limit fails instead of showing incomplete history.
Missing or expired versions never fall back to current content.
Source changes close the browser; changed selections or destinations invalidate pending confirmation.
